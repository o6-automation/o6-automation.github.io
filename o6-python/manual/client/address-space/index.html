Working with the address space¶

Reading attributes¶

read() is the workhorse. In its simplest form it reads the Value attribute of one node and gives you a Python value:

value = client.read("ns=1;s=IntegerVariable")

The target is anything a NodeId can be built from: a NodeId string, an o6.NodeId, an ExpandedNodeId, a Node object, or a generated type class:

client.read(o6.NodeId(2255))                       # NamespaceArray
client.read(client["ns=1;s=IntegerVariable"])      # a Node object
client.read(ns0.objtypes.BaseObjectType, attr="browseName")

Passing a list reads all of them in a single Read request, which is the whole point — one round trip instead of n:

values = client.read([
    "ns=1;s=IntegerVariable",
    "ns=1;s=DoubleVariable",
])
# [np.int32(42), np.float64(3.14159)]

Numeric values come back as NumPy scalars and arrays, which preserves the exact OPC UA data type (Int32 stays 32 bit) and makes array data cheap to work with.

Choosing the attribute¶

attr selects which attribute to read. It accepts an o6.AttributeId member or a name as a string, matched case-insensitively and ignoring separators:

client.read("ns=1;s=IntegerVariable", attr=o6.AttributeId.NODE_CLASS)
client.read("ns=1;s=IntegerVariable", attr="browseName")   # same as BROWSE_NAME
client.read("ns=1;s=IntegerVariable", attr="access_level")

This is how you get at metadata: BROWSE_NAME, DISPLAY_NAME, DESCRIPTION, DATA_TYPE, VALUE_RANK, ARRAY_DIMENSIONS, ACCESS_LEVEL, HISTORIZING, DATA_TYPE_DEFINITION, and the rest of o6.AttributeId.

Values, or the whole DataValue¶

By default read() returns the value for every Good-severity status, including informational codes and flags, and raises for Uncertain or Bad. Choosing valueOnly=True discards status and timestamps; use valueOnly=False to receive DataValues and interpret their quality yourself. Service failures still raise. The range-error handling described below also applies in this mode:

dv = client.read("ns=1;s=IntegerVariable", valueOnly=False)
print(dv.value, dv.status, dv.sourceTimestamp, dv.serverTimestamp)

This is the form to use when you need status details, including information carried by a successful read, or timestamps.

timestampsToReturn selects SOURCE, SERVER, BOTH, or NEITHER from ns0.datatypes.TimestampsToReturn. Omitting it (or passing None) selects SOURCE on both client and server.

Index ranges¶

range reads a slice of an array variable instead of the whole thing. It takes OPC UA's inclusive string syntax or Python slices, which are stop-exclusive as usual:

client.read("ns=1;s=ArrayVariable", range="1:3")            # elements 1,2,3
client.read("ns=1;s=ArrayVariable", range=slice(1, 4))      # identical
client.read("ns=1;s=ArrayVariable", range=(slice(1, 4),))   # identical
client.read("ns=1;s=Matrix", range="1:3,4:6")               # two dimensions
client.read("ns=1;s=Matrix", range=(slice(1, 4), slice(4, 7)))

Slices must have explicit non-negative bounds and no step — OPC UA's NumericRange cannot express anything else, and violations raise ValueError before a request is sent. With a list of targets you may pass a list of ranges, one per target. Invalid, out-of-bounds, and non-array ranges follow the ordinary read error policy below. With valueOnly=False, the returned DataValue retains its original error status; batch reads return one DataValue per target.

A scalar range broadcasts across a target list; a range list must have exactly one entry per target. None and "" request the entire attribute. A nonempty range on a non-Value attribute returns BAD_INDEX_RANGE_NO_DATA using the same raw/value-only error policy. Invalid range strings are OPC UA status failures; malformed Python slices raise TypeError or ValueError.

An empty target list returns [] without issuing a request, including when the client is disconnected. Options and range-list lengths are still validated. Unsupported Python argument types raise TypeError; unknown attribute names, invalid slices and mismatched range-list lengths raise ValueError. valueOnly must be a bool. Only a Python list selects batch mode.

What read raises¶

Client and server reads share this error contract:

Situation Result
Good severity, valueOnly=True returns the value, discarding status and timestamps
Single target, Uncertain or Bad, valueOnly=True raises o6.StatusCodeError
List of targets, any Uncertain or Bad, valueOnly=True raises o6.StatusCodeError with the failed index in __notes__
Any per-target status, valueOnly=False returns the DataValue; inspect DataValue.status
Service itself failed raises o6.StatusCodeError; .code retains serviceResult
Client not connected raises RuntimeError("Client is not connected")

Callable node() reads follow the value-only policy too. Write return values and StatusCode.check() are unchanged; check() still compares exact codes.

client.read("ns=1;s=DoesNotExist")
# o6.StatusCodeError: BAD_NODE_ID_UNKNOWN

Writing attributes¶

write() mirrors read() and comes in three shapes.

One node, one value:

status = client.write("ns=1;s=IntegerVariable", 42)

Parallel lists, when you want per-node index ranges:

statuses = client.write(
    ["ns=1;s=IntegerVariable", "ns=1;s=DoubleVariable"],
    [100, 2.7182],
)

Or a mapping, which is the most readable form for a batch:

statuses = client.write({
    "ns=1;s=IntegerVariable": 100,
    "ns=1;s=DoubleVariable": 2.7182,
})

Nonempty writes are sent as one Write request. The single-node form returns one o6.StatusCode; the list and mapping forms return a list of status codes in input order, including a one-element batch. Empty lists/mappings return [] without a service call. The value argument must be omitted for the mapping form, and must be a list of matching length for the list form — anything else raises ValueError before writing. Even explicit value=None conflicts with a mapping. A list value for one scalar target is an array. All targets are attempted despite per-target failures; writes do not provide rollback. Server.write uses these same argument shapes and result types with local administrative privileges.

Explicit None writes a null value in scalar, list, and mapping forms, just as o6.DataValue(value=None) does. Nullable targets such as String variables accept it; non-nullable numeric targets return BAD_TYPE_MISMATCH and keep their value. A typed empty array, such as numpy.array([], dtype=numpy.int32), is an array with zero elements, not a null value. Omitting the value in client.write(node) raises ValueError. For callable nodes, node() reads and node(None) writes a null, raising StatusCodeError if the target rejects it.

attr works exactly as in read(), so writes are not restricted to values:

client.write("ns=1;s=IntegerVariable", o6.LocalizedText("Counter"), attr="displayName")

range accepts an inclusive string, a stop-exclusive slice or tuple of slices, a broadcast range, or a per-target list. None and "" mean the whole attribute. Nonempty ranges require the Value attribute. It is supported for the single-node and list forms (not the mapping form, which has nowhere to put it):

client.write("ns=1;s=ArrayVariable", [99, 98], range="1:2")

To supply a status code or timestamps along with the value, pass a DataValue instead of a bare Python value. The server must permit it — writing timestamps requires AccessLevelType.TIMESTAMP_WRITE, writing a status requires STATUS_WRITE, and without them the write comes back BAD_WRITE_NOT_SUPPORTED:

dv = o6.DataValue()
dv.value = o6.Int32(77)
client.write("ns=1;s=IntegerVariable", dv)

Unlike read(), Client.write() never raises for a bad per-node status — the status code is the return value. Service-level failures raise o6.StatusCodeError with the actual .code; Python input errors raise TypeError or ValueError. Check results explicitly, either directly or with StatusCode.check(), which raises StatusCodeError for anything but GOOD:

status = client.write("ns=1;s=IntegerVariable", "not an int")
print(status)                      # BAD_TYPE_MISMATCH
if o6.StatusCode.BAD in status:    # StatusCode is a full IntFlag
    ...
status.check()                     # raises o6.StatusCodeError

The node(value) shorthand checks the write result and raises StatusCodeError on rejection, in both synchronous and asynchronous code.

Client, server, and callable-node writes accept the same payloads. Ordinary Value writes retain type inference, so client.write(node, 123) remains valid when its inferred datatype matches the node. Use explicitly typed NumPy numbers when exact width or signedness matters.

Non-Value attributes require their expected datatype: use o6.LocalizedText("Description"), o6.QualifiedName("Name"), or numpy.uint8(3) for Description, BrowseName, or AccessLevel respectively. No attribute-specific coercion is applied. A value-only DataValue envelope is also accepted; explicit status or timestamp fields on non-Value attributes return BAD_WRITE_NOT_SUPPORTED, including an explicitly supplied GOOD status.

Calling methods¶

call() invokes an OPC UA method. It needs the object that owns the method, the method itself, and the input arguments in declaration order:

status, greeting = client.call(
    "ns=1;s=TestMethods",
    "ns=1;s=MethodHelloString",
    ["World"],
)
# (StatusCode.GOOD, 'Hello World!')

The return value is always a tuple whose first element is the method's status code, followed by the decoded output arguments — so a method with no outputs returns a one-element tuple. Node objects inside inputArgs are converted to their NodeIds automatically, at any nesting depth, so you can pass nodes where a method expects a NodeId.

A failing service raises o6.StatusCodeError, with the original status in .code. A method that returns a bad status code does not raise; invalid method selection and argument validation also return status tuples. Available outputs are preserved, so inspect the status before using them. Python argument conversion failures remain Python exceptions such as TypeError. server.call() follows the same result contract with administrative privileges; remote calls check session permissions. BAD_INVALID_ARGUMENT almost always means the argument list does not match the method's InputArguments declaration in count, type, or value rank.

The Node API offers the same call in object syntax, which reads better when you already hold the node:

client.objects.testMethods.MethodHelloString("World")

Typed Method node calls check the method status and raise StatusCodeError on failure. Their successful tuple includes the status and outputs. Remote Method nodes now perform this check explicitly; use client.call() when a bad status should be returned as data. Both forms can be awaited from async code.

Browsing¶

browse() follows references from a node and returns a flat list of ReferenceDescription objects. Continuation points are handled internally: the call issues BrowseNext as often as needed, so the list is always complete even when the server chunks its response, including empty intermediate pages. server.browse() accepts the same filters and returns the same list shape. Node and NodeId targets work in synchronous code; async tasks await the call. Service and per-result failures raise o6.StatusCodeError. On failure or cancellation, collection attempts to release the outstanding continuation point; a lost connection can prevent release.

For explicit client pagination, use serviceBrowse and serviceBrowseNext, checking response-header and per-result statuses yourself. Local server paging uses browsePage and browseNext; see explicit pages and migration.

references = client.browse("i=85")

There is one thing to know before using the result, and it catches everyone once: the default resultMask is empty, so the server only fills in the target nodeId and leaves browseName, displayName, nodeClass, referenceTypeId, isForward, and typeDefinition at their zero values. Ask for the fields you need:

from o6.ns import ns0

for ref in client.browse("i=85", resultMask=ns0.datatypes.BrowseResultMask.ALL):
    print(ref.browseName, ref.nodeClass, ref.nodeId, ref.typeDefinition)

The remaining parameters narrow the traversal:

references = client.browse(
    "ns=1;s=Plant",
    direction=ns0.datatypes.BrowseDirection.FORWARD,   # FORWARD, INVERSE, BOTH
    reftype=ns0.reftypes.HasComponent,                 # reference type to follow
    refsubtypes=True,                                  # include its subtypes
    nodeClassMask=ns0.datatypes.NodeClass.VARIABLE,    # only Variables
    resultMask=ns0.datatypes.BrowseResultMask.ALL,
)

reftype defaults to HierarchicalReferences with refsubtypes=True, which is the "show me the children" traversal. INVERSE walks to the parent. nodeClassMask defaults to UNSPECIFIED, meaning every node class.

To resolve a path rather than enumerate children, use the browse-path syntax on a node — that goes through TranslateBrowsePathsToNodeIds:

node, = client.objects["/1:Plant/1:IntegerVariable"]

Browsing interactively¶

For exploring an unfamiliar server there is a fully interactive browser built into the client:

selected = client.browseInteractive()          # starts at Objects
selected = client.browseInteractive("i=85")    # or anywhere else

It needs curses (on Windows: pip install windows-curses, otherwise ImportError). Quitting with n or p returns the selected NodeId or browse path as a string so you can paste it straight into code; any other exit returns None.

Namespaces and NodeIds¶

A NodeId string like "ns=1;s=IntegerVariable" is namespace-relative, and the index 1 means something different on every server. o6 resolves this for you, which is why connect() spends two of its steps on namespaces.

On connect, the client reads the server's ApplicationUri and registers it in the process-wide namespace table under the shortname <clientname>_ns1, scoped to the endpoint URL. Then updateRemoteNamespaces() reads the server's NamespaceArray and maps every remaining namespace URI onto a compiled namespace module, scoped to the client name. Where several compiled versions of the same URI exist, the client reads the server's NamespaceMetadata (its NamespaceVersion) and picks the matching one, falling back to the newest available and logging a warning if the server is newer than anything you have compiled.

The visible effect is that ns=1 in your code means "namespace 1 of the server this client is connected to", and NodeIds returned to you print with the resolved shortname:

print(client.read("ns=1;s=IntegerVariable", attr="browseName"))
# client1_ns1:IntegerVariable

info = o6.ns.client1_ns1
print(info.uri, info.scope, info.index)
# urn:open62541.unconfigured.application  opc.tcp://localhost:4840  129

If a connected server adds namespaces at runtime, call client.updateRemoteNamespaces() again. It builds the new mapping — Python namespace table, SecureChannel decoder mapping, and custom data type chain — and swaps it in as one snapshot; a failed refresh leaves the previous, working snapshot in place, and an unchanged one is not rebuilt.

To discover the structure definitions of a server's custom data types, use getRemoteDataTypes(). Automatic discovery follows every browse page and preserves numeric, string, GUID, and opaque NodeIds. References with a remote server index or namespace URI are skipped because they cannot be read as local NodeIds through this session. Failed browse/read services and attribute reads raise StatusCodeError; types without the optional DataTypeDefinition attribute are skipped:

for dt in client.getRemoteDataTypes():
    print(dt["typeName"], dt["typeId"], dt["structureType"], dt["membersSize"])

It walks the DataType hierarchy below Structure (i=22) and reads DataTypeDefinition and BrowseName for every node it finds, returning one dict per type with the keys typeName, typeId, binaryEncodingId, structureType, and membersSize. Only nodes that actually carry a StructureDefinition — structures, structures with optional fields, and unions — appear. Pass a list of DataType NodeIds to query just those instead of walking the tree; an empty list returns [] without contacting the server.

The namespace machinery itself is described in Namespace mapping in o6, and loading nodesets so that custom types decode into real Python classes is covered in Loading and using nodesets.

The Node API from a client¶

Everything above addresses nodes by NodeId. The Node API lets you address them the way the server models them — as an object graph. A connected client exposes the four standard entry points as live nodes:

client.root       # i=84
client.objects    # i=85
client.types      # i=86
client.views      # i=87

Attribute access resolves a child by BrowseName through a Browse request and caches it; calling a node reads or writes it; indexing resolves a browse path:

client.objects.plant.integerVariable()            # read the Value
client.objects.plant.integerVariable(42)          # write the Value
client.objects.plant.integerVariable(attr="browseName")
client.objects.testMethods.MethodHelloString("World")

dir() on a node browses it and returns its children, so tab completion walks the live address space: type client.objects. in a REPL and the server's actual nodes are offered, one Browse request at a time. That is the fastest way to explore an unfamiliar server, and it is why the dotted form is worth using even when you already know the NodeId.

BrowseNames are not Python identifiers — sometimes you need []

A BrowseName is an arbitrary OPC UA string. A Python attribute name is an identifier. Dot syntax can only reach the children whose BrowseName happens to be a valid identifier, and dir() deliberately lists only those — so a child missing from tab completion is not missing from the server.

Within that subset, lookup matches the BrowseName exactly first and then case-insensitively, so ServerStatus and serverStatus both resolve. Completion offers the spelling the generated declarations use: instances (Objects, Variables, Methods, Views) with a lowercased first letter, type nodes (ObjectType, VariableType, ReferenceType, DataType) in their original PascalCase.

Everything else goes through the browse-path form, node["/<ns>:<BrowseName>"]:

plant = client.objects.plant

plant["/1:Device Name"]      # spaces
plant["/1:2Fast"]            # leading digit
plant["/1:Motor-Current"]    # dashes and other punctuation
plant["/1:class"]            # a Python keyword
plant["/1:Set&.Point"]       # '.' escaped with '&'

., /, &, <, >, :, #, and ! are reserved in a browse path and are escaped with a leading &.

The other case that needs [] is ambiguity. When two references from the same node carry the same BrowseName, dot access refuses to guess and raises AttributeError listing the candidates, while the browse path returns all matches — indexing always returns a list, even for a single hit:

plant.shared                 # AttributeError: ... is ambiguous; 2 matching references
plant["/1:Shared"]           # [VariableNode(...Dup1), VariableNode(...Dup2)]
node, = plant["/1:Temperature"]

Indexing the client itself resolves a NodeId into a typed node without knowing its node class up front. It reads NodeClass and BrowseName and returns the matching subclass — VariableNode, ObjectNode, MethodNode, and so on:

node = client["ns=1;s=IntegerVariable"]
print(repr(node))     # client1_ns1:IntegerVariable: VariableNode(ns=1;s=IntegerVariable)

An unknown NodeId raises StatusCodeError with code BAD_NODE_ID_UNKNOWN, matching server[nodeId]. A browse path that resolves to nothing raises KeyError; a missing child raises AttributeError. In async code every form is awaited:

node = await client["ns=1;s=IntegerVariable"]
value = await client.objects.plant.integerVariable()

The Node API usage guide and the Node API syntax tutorial go through this in detail.

Changing the server's address space¶

A client can modify a remote address space, provided the server allows it. There is one method per node class, all keyword-only, all returning the NodeId the server assigned:

from o6.ns import ns0

attrs = ns0.datatypes.VariableAttributes()
attrs.displayName = o6.LocalizedText("FromClient")
attrs.dataType = o6.NodeId(ns0.datatypes.Int32)
attrs.valueRank = int(o6.ValueRank.SCALAR)
attrs.accessLevel = int(
    ns0.datatypes.AccessLevelType.CURRENT_READ
    | ns0.datatypes.AccessLevelType.CURRENT_WRITE
)
attrs.value = o6.Int32(7)

nodeId = client.addVariableNode(
    parent="ns=1;s=Plant",
    browseName=o6.QualifiedName(1, "FromClient"),
    attributes=attrs,
    requestedNodeId="ns=1;s=FromClient",     # optional; omit to let the server pick
)

The family is addVariableNode, addVariableTypeNode, addObjectNode, addObjectTypeNode, addViewNode, addReferenceTypeNode, addDataTypeNode, and addMethodNode. Each takes parent, browseName, attributes (the matching *Attributes structure), an optional requestedNodeId, and a parentReference that defaults sensibly per node class — HasComponent for Variables, Objects, Views, and Methods, HasSubtype for the type node classes. addVariableNode and addObjectNode additionally take a typeDefinition, defaulting to BaseDataVariableType and BaseObjectType.

References and nodes can be removed and rewired:

client.addReference("i=85", ns0.reftypes.Organizes, nodeId)
client.deleteReference("i=85", ns0.reftypes.Organizes, nodeId)
client.deleteNode(nodeId)                      # or a list of NodeIds

addReference and deleteReference return the individual StatusCode (await it inside async tasks). Rejected mutations return non-Good statuses; service failures raise StatusCodeError. Use forward=False for inverse edges and deleteBidirectional=False to remove only the requested edge. Both accept expanded targets and preserve their remote metadata. Creation also accepts targetNodeClass and targetServerUri for validation by the remote server. The server uses the same canonical arguments; see reference migration and local metadata capabilities.

deleteNode(nodeId, deleteTargetReferences=True) accepts one Node or NodeId-like target, or a list. A scalar target returns one StatusCode; a list returns one status per target in input order, including a one-element list. Every target is attempted despite individual failures, and an empty list returns [] without a request. Call status.check() on each result to raise for individual failures; service failures raise StatusCodeError. Malformed Python arguments raise TypeError or ValueError before deletion starts. Await the operation in async tasks.

targets = [firstNode, "ns=1;s=Missing", lastNode]
statuses = client.deleteNode(targets)
for target, status in zip(targets, statuses):
    print(target, status)

Batch calls previously returned one aggregate status. Update callers to inspect the returned list; scalar calls retain their existing return type.

deleteTargetReferences=True removes incoming references from remaining nodes; False leaves dangling references. Browse omits those edges until the target NodeId is reused. The native stack can also delete hierarchical children that have no other parent, with either flag. Client operations use the remote session's permissions. See server deletion and migration for the matching local administrative API and retained-handle behavior.

Note that a client adding a Method node can only create the node, not its behaviour: the implementation lives on the server. See Server for that side.

Creating nodes with friendly inputs¶

addObject and addVariable match the server conveniences and return typed handles. In async tasks, await both creation and subsequent node operations.

parent = client.addObject("Plant", client.objects)
temperature = client.addVariable("Temperature", parent, 22.5)
print(temperature())

Use nodeId, typeDefinition, and ns to control identity and naming; variables also accept dataType and writable. Numeric and array inference matches the server, including typed empty arrays. Both APIs default parentReference to Organizes and allow an explicit reference type. Existing attribute-based addObjectNode and addVariableNode retain their NodeId results and HasComponent default. Local history registration and Python behavior installation remain server-only capabilities.

If a client convenience is cancelled after the server creates the node, it attempts to remove that node before propagating cancellation. Cleanup requires a working connection; a failed cleanup is attached as an exception note.

Paging and translating browse paths¶

Both APIs expose browsePage(target, maxReferences=...) and browseNext(releaseContinuationPoint, continuationPoint). browsePage returns one BrowseResult; browseNext accepts a token or list/tuple and always returns a list of results. An empty token list returns []. Tokens belong to the issuing server/session. Release unused tokens when abandoning a traversal:

page = client.browsePage(parent, maxReferences=10)
try:
    for reference in page.references:
        print(reference.nodeId)
finally:
    if page.continuationPoint:
        client.browseNext(True, page.continuationPoint)

browse still collects every page automatically. Paging conveniences raise on service or per-page failures and attempt token release on failure/cancellation.

translateBrowsePathsToNodeIds accepts a BrowsePath or a list, returning one BrowsePathResult or a list in the same order. [] returns []; path failures remain in each result's status and service failures raise. browseSimplifiedBrowsePaths(origin, ["1:Plant", "1:Temperature"]) resolves one BrowseName chain through forward hierarchical references. It returns one BrowsePathResult, including an unresolved-path status. Both helpers have the same contracts on client and server.

serviceTranslateBrowsePathsToNodeIds preserves raw request/response access on both APIs; the existing server translateBrowsePaths(request) name is retained. server.browseRecursive remains a local native traversal. Await all these dual-mode operations from async tasks.

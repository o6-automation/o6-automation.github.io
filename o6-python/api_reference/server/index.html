Server¶

Canonical path: o6.server.Server

Root shortcut: o6.Server

Server ¶

Bases: _NativeServer

High-level OPC UA server.

server = o6.Server(port=4840)
with server:
    temperature = server.addVariable("Temperature", server.objectsNode, 22.5)
    print(temperature())

Return behavior depends on the operation and caller loop. Node creation returns handles directly except for async tasks calling a running worker from another loop, which receive awaitables; see MaybeAwaitable.

See the Server guide for the whole picture, and Server callbacks for behaviour implementation.

Install server-local Python behaviour on a UA type or concrete node.

implement(DeclarationType, ImplementationType) binds an undecorated Python behaviour subclass to an existing ObjectType or VariableType on this server alone. Future instances created through native APIs or an AddNodes request receive that implementation, without modifying or subclassing the UA information model. Their implementation-selected children are created before the native Mandatory children, and their ordinary Python initializer runs once, after the complete subtree exists. Because AddNodes supplies no Python arguments, that initializer must be callable without required arguments. Passing None restores the declaration's own Python type for future instances.

Passing None positionally for a concrete Method or Variable restores the callback resolution performed during construction. A concrete value positionally supplied for a Variable removes both callbacks and installs that value in native storage.

call=, read=, and write= replace or clear one callback slot on a Method, Variable, or VariableType. Existing concrete instances are never changed by a type-level update.

createEvent ¶

createEvent(
    eventType=None,
    *,
    source=ns0.instances.server,
    message="",
    severity=1,
    fields=None,
    eventInstance=None
)

Emit an event and return its generated EventId.

Matches C's UA_Server_createEvent: this emits immediately. Construct o6.Event(server, ...) for a reusable draft. emitEvent is an alias.

An explicit eventType wins; otherwise use eventInstance's type when supplied, then source's declared GeneratesEvent target. Without an instance, no declared target falls back to BaseEventType; ambiguous targets or a source without a type definition raise ValueError.

eventInstance optionally supplies fields from an existing Object instance of BaseEventType or a subtype. Node handles must belong to this server; NodeIds are resolved locally. Explicit fields take precedence over instance properties, then standard defaults apply. Stored EventType and SourceNode properties also override emission arguments, including when their values are null NodeIds, matching C. The instance is read without being updated or deleted.

Returns the EventId directly for synchronous callers, or an awaitable for asynchronous callers on another event loop.

start ¶

start()

Start the server networking layer.

Synchronous callers wait until the listeners are ready, using a background thread to drive I/O. On the server's running asyncio loop, await waitReady() afterwards, or use async with server. Listener creation failures are raised by the readiness wait.

waitReady async ¶

waitReady()

Wait for a started server's listeners, raising any bind failure.

Call on server.loop after start(). Cancelling this wait shuts down startup and closes any listeners already opened.

stop ¶

stop()

Shut down the server.

Calls from a background server's own loop initiate shutdown and return a Task that can be awaited. Other callers block until shutdown finishes. The server's worker is stopped after the shutdown task completes.

historize ¶

historize(
    target, *, capacity=0, strategy="on-write", interval=1.0
)

Record the history of an existing Variable.

addVariable(..., historizing=...) covers Variables this server creates. This is for the ones it does not: nodes loaded from a nodeset, declared instances, or nodes a client added. It sets the Historizing attribute and the history access bits as well as registering the node, so a Variable that was not marked historizing becomes one.

This takes effect immediately and needs a history database already configured. Variables created with historizing= register immediately when running, or during start() when created before startup. Await this method from async code; synchronous callers block until it completes. Failed registration restores the original node attributes.

server.config.setHistoryDatabase(capacity=5000)
server.historize("ns=1;s=Level")
server.historize(sensorNode, strategy="poll", interval=0.2)

Parameters:

Name Type Description Default
target NodeIdLike

The Variable to historize.

 required
capacity int | None

Samples kept for this node; 0 takes the database default, None grows the store instead of evicting.

 0
strategy str

"on-write" or "poll".

 'on-write'
interval float

Seconds between samples, for "poll" only.

 1.0

Raises:

Type Description
